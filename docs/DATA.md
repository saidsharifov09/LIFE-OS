# Данные Life OS

Основная база — **IndexedDB на устройстве** (через [Dexie](https://dexie.org)), имя базы `lifeos`.
Приложение полностью работает без интернета. Облачная синхронизация (Этап 4.5) будет надстройкой.

Код: `src/db/db.ts` (схема), `src/db/types.ts` (типы).

## Общие правила записей

Каждая запись пользовательских таблиц имеет:

| Поле | Смысл |
|---|---|
| `id` | строка-UUID |
| `createdAt` / `updatedAt` | время в мс; `updatedAt` меняется при любой правке (нужно для синхронизации «новее побеждает») |
| `deletedAt` | мягкое удаление → корзина (30 дней). Списки показывают только записи без `deletedAt` |
| `demo` | `true` — демо-запись, удаляется кнопкой «Удалить демо-данные» |

Даты — строки `YYYY-MM-DD` в **локальном** времени, время — `HH:mm`. Это избавляет от сдвигов часовых поясов.

Булевы поля (`done`, `processed`, `pinned`…) **не индексируются** — IndexedDB не умеет индексировать boolean.

## Таблицы (схема v1)

| Таблица | Что хранит | Индексы |
|---|---|---|
| `tasks` | задачи: дата, время, приоритет 0–3, категория, подзадачи, повтор, `topDate` (один из 3 главных на дату), `eventId` | date, topDate |
| `events` | события: дата, начало (null — весь день), длительность (мин), цвет, повтор, `exdates` (пропущенные вхождения), `taskId`, `remind` | date, taskId |
| `inbox` | записи быстрого захвата: текст, подсказки (`hints`), `processed` | createdAt |
| `accounts` | счета: тип, валюта, начальный остаток, цвет, `archived`. Текущий остаток считается по операциям | — |
| `transactions` | доходы/расходы/переводы: сумма, валюта, категория, дата; у перевода `toAccountId`, `toAmount` (разные валюты), `savingsId` (копилка); `recurringId` — оплата регулярного платежа | date, type, accountId, category |
| `budgets` | лимит на месяц по категории расходов, в рублях; `category = '__total'` — общий бюджет (v2) | category |
| `recurring` | регулярные платежи/подписки/доходы: сумма, повтор, `startDate`, `nextDate`, `active` (v2) | nextDate |
| `debts` | долги: `direction` (they_owe / i_owe), сумма, `paid`, срок, `closed` (v2) | — |
| `savings` | копилки: цель, `saved`, срок, цвет (v2) | — |
| `notes` | заметки: заголовок, текст, `sectionId`, `tags` (без «#», строчными), `pinned`, `archived`, `images` (сжатые JPEG data URL, до 6 шт., v4). Ссылки не хранятся отдельно — берутся из текста | sectionId |
| `noteSections` | разделы блокнота: имя, эмодзи `icon`, `order`. Стартовые — с **id `sec_default_N`** (одни и те же на всех устройствах) | order |
| `later` | «Посмотреть позже»: `kind` (video/movie/series/article/book/link/other), `url`, `done`, `doneAt`, `note` (v4) | — |
| `log` | история (Life Log): `kind` (activity/place/people/learned/decision/note/evening), дата, время, `mood`, `personIds` (с кем, v4) | date, kind |
| `people` | люди: `relation`, цвет, `birthday` (`MM-DD`) + необязательный `birthYear`, `phone`, `notes`, `topics` («что обсудить»), `lastContact`, `contactEvery` (дней), `favorite` (v4) | — |
| `reviews` | отметки об утреннем обзоре/вечернем отчёте | [date+kind] |
| `goals` | цели: `why` (зачем), срок, цвет, эмодзи, `milestones` (этапы), ручной `progress`, `done` (v3) | — |
| `habits` | привычки: эмодзи, цвет, `days` (дни недели, пусто — каждый день), `target` (раз в день), `goalId`, `order` (v3) | order |
| `habitChecks` | отметки привычек: **id = `${habitId}_${date}`** — одна запись на день, `count` (v3) | habitId, date |
| `health` | здоровье за день: **id = `day_${date}`**, сон (ч), вода (стаканы), вес (кг), настроение и самочувствие 1–5 (v3) | date |
| `workouts` | тренировки: дата, вид, минуты (v3) | date |
| `settings` | ключ-значение: `rates` (курсы), `defaultAccount`, `homeWidgets` (порядок виджетов главной), `homeHidden` (скрытые виджеты), `hiddenSections` (скрытые разделы меню)… — синхронизируются | key |

Настройки конкретного устройства (тема, «упростить размытие», вид календаря, недавние запросы поиска, PIN-код `lifeos.pin` — только хеш с солью) лежат в `localStorage`: не синхронизируются и не попадают в копию.

### Финансы: как считаются деньги

- Остаток счёта (в его валюте) = начальный + доходы − расходы − переводы со счёта + переводы на счёт. Операция в другой валюте пересчитывается по курсу.
- Все итоги, бюджеты и графики — в рублях по курсам из `settings.rates` (по умолчанию 1 $ = 92 ₽, 1 смн = 8.5 ₽).
- Переводы (между счетами и в копилки) не считаются ни доходом, ни расходом.
- Чистые функции расчётов — `src/lib/finance.ts` (с тестами), действия — `src/actions/money.ts`.

### Повторы

`Recurrence = { freq: 'daily'|'weekly'|'monthly'|'yearly', interval, days?, until? }`, дни недели 0 = понедельник.
- Задачи: при выполнении повторяющейся задачи создаётся новая копия на следующую дату, у выполненной повтор снимается.
- События: хранится одна запись, вхождения вычисляются на лету (`expandEvents`). Перенос серии сдвигает дату начала.

### Люди и история

- День рождения хранится без года (`MM-DD`), год — отдельно и по желанию. 29 февраля в невисокосный год считается 28-го
  (в .ics — `BYMONTH=2;BYMONTHDAY=-1`). Расчёты — `src/lib/people.ts` (с тестами).
- Запись истории с людьми (`personIds`) сдвигает их `lastContact` вперёд (но не назад), отменяется вместе с записью.
- Удаление раздела блокнота переносит его заметки в «Разное» (или в первый оставшийся раздел); последний раздел удалить нельзя.

## Корзина

Удаление = `deletedAt` (мягкое). Экран `/trash` (Настройки → Данные → Корзина) показывает такие записи из всех таблиц,
их можно вернуть или удалить навсегда. При запуске `autoPurgeTrash()` удаляет всё, что лежит в корзине дольше 30 дней.

## Резервная копия (файл JSON)

```jsonc
{ "app": "life-os", "format": 1, "schemaVersion": 2, "exportedAt": 1764240000000,
  "tables": { "tasks": [...], "events": [...], ... },   // все таблицы, включая записи в корзине
  "settings": [{ "key": "rates", "value": {...}, "updatedAt": ... }] }
```

- Настройки устройства (`lastBackupAt`, `backupSnoozeUntil`) в копию не попадают; тема и т. п. — в localStorage.
- **Зашифрованная копия**: `{ app, format, encrypted: true, kdf: { PBKDF2, SHA-256, iterations: 310000, salt },
  cipher: { AES-GCM, iv }, data }`, где `data` — base64 от зашифрованного JSON обычной копии. Ключ 256 бит выводится
  из пароля; AES-GCM проверяет целостность, поэтому неверный пароль и повреждённый файл дают одну ошибку.
- **Импорт**: «объединить» — по `id`, при совпадении побеждает больший `updatedAt` (удаление тоже правка: `deletedAt`
  из более новой копии переносится); «заменить» — на устройстве остаётся ровно содержимое копии.
  Импорт — одно действие `runAction`, «Отменить» в тосте откатывает его целиком (настройки не откатываются).
- Копия из **более новой** схемы не импортируется (просьба обновить приложение); из более старой — проходит через
  `migrateTables()` в `src/lib/backup.ts`.

## Облако (Этап 4.5)

Схема — `supabase/schema.sql`, инструкция — [docs/SUPABASE.md](SUPABASE.md), код — `src/sync/`.

| Таблица Supabase | Поля |
|---|---|
| `records` | `user_id`, `tbl` (имя таблицы или `settings`), `id`, `updated_at` (мс), `deleted`, `data` (base64: iv + AES-GCM от JSON записи), `seq` (номер изменения на сервере) |
| `vault` | `user_id`, `salt`, `iterations`, `check_data` (зашифрованная контрольная строка) |

На устройстве — отдельная служебная база `lifeos-sync` (не входит в резервные копии): `kv` (ключ шифрования как
неизвлекаемый CryptoKey, `lastSeq`, `lastSyncAt`, `userId`) и `pushed` (`таблица:id` → хеш последней известной версии).
Адрес проекта и сессия входа — в localStorage (`lifeos.sync.config`, `lifeos.sync.session`).

## Версии схемы и миграции

| Версия | Этап | Изменения |
|---|---|---|
| 1 | 0–2 | стартовая схема |
| 2 | 3 | `budgets`, `recurring`, `debts`, `savings`; новые необязательные поля `transactions` (без миграции данных) |
| 3 | 5 | `goals`, `habits`, `habitChecks`, `health`, `workouts` (без миграции данных) |
| 4 | 6 | `people`; необязательные поля `notes.images`, `later.doneAt/note`, `log.personIds` (без миграции данных) |

Правила:
1. **Никогда не менять** существующие `this.version(N)` — только добавлять `this.version(N+1).stores({...}).upgrade(tx => ...)`.
2. Указывать в `stores` только изменившиеся таблицы.
3. Обновлять `SCHEMA_VERSION` в `src/db/db.ts` и эту таблицу.
4. Резервная копия хранит `schemaVersion`; если миграция меняет данные, добавить тот же шаг в `migrateTables()` (`src/lib/backup.ts`).
