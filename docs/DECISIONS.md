# Решения (журнал)

Принятые без вопросов решения — с причинами. Новые добавлять сверху раздела этапа.

## Этап 4.5 — Облако и синхронизация (2026-11-27)

1. **Supabase на чистом `fetch`, без `supabase-js`** (`src/sync/api.ts`): нужны всего 4 вызова входа и 3 запроса к
   таблицам — не тащим ~50 КБ библиотеки на слабый ноутбук и iPhone.
2. **Адрес и публичный ключ — в настройках приложения, не в коде** (localStorage устройства). Ключ `anon`/`publishable`
   публичный по замыслу Supabase; данные защищают вход и RLS. Репозиторий публичный — так он остаётся без ключей,
   и сборка GitHub Pages ничего не знает о проекте.
3. **Вход по 6-значному коду**, а не по ссылке: на iPhone ссылка из письма открывается в Safari, у которого другое
   хранилище, чем у приложения на экране «Домой» — вход «потерялся» бы. Ссылка тоже поддерживается (для ноутбука).
4. **Сквозное шифрование**: пароль синхронизации → PBKDF2-SHA256 (310 000 итераций, соль из облачного «сейфа») →
   AES-GCM 256, у каждой записи свой iv. В облаке открыто видны только раздел, случайный id, время правки и признак
   удаления — это нужно серверу для «новее побеждает». Второе устройство проверяет пароль, расшифровывая контрольную
   строку из «сейфа». Ключ хранится на устройстве **неизвлекаемым** CryptoKey в отдельной базе `lifeos-sync`
   (пароль вводится один раз на устройстве, а прочитать сам ключ нельзя даже из кода приложения).
5. **Конфликты: «новее побеждает» по `updatedAt`** — и на устройстве, и на сервере (триггер не даёт старой правке
   затереть новую). Часы устройств могут расходиться на секунды — для личного приложения приемлемо.
6. **Что отправлять — по хешу записи**, а не по флагам «изменено»: служебная база помнит хеш последней отправленной/
   полученной версии. Так ничего не теряется, даже если приложение закрыли посреди работы, и не нужно трогать слой
   действий. Окончательно удалённые записи определяются как «были отправлены, а теперь их нет» → «надгробие».
   Запись, которую устройство само удалило навсегда, не «воскресает», если из облака пришла та же старая версия.
7. **Номер изменения на сервере (`seq`)** — забираем только то, что новее последнего известного номера.
8. **Когда синхронизируется**: при запуске, через 3 с после любого изменения в базе (`Dexie.on('storagemutated')`),
   при появлении сети, при возвращении в приложение и раз в минуту, пока оно открыто.
9. **Настройки устройства не синхронизируются** (тема, «последняя копия», сама синхронизация); курсы, счёт по умолчанию,
   порядок виджетов — синхронизируются.
10. **Запасной вариант, если Supabase недоступен** (в России его временно блокировали): адрес в настройках может быть
    любым, поэтому подходит бесплатный прокси на Cloudflare Workers (скрипт из 6 строк в docs/SUPABASE.md) — шифрование
    то же. Последний запасной вариант без облака — файл резервной копии.
11. **Проверка**: SQL-схема прогнана на PostgreSQL 16 (RLS: чужие строки не видны и не пишутся; anon заблокирован;
    старая правка не затирает новую). Браузерная проверка — два устройства на заглушке API Supabase.
    На настоящем Supabase в облачной сессии проверить нельзя (нет аккаунта) — первым реальным подключением будет ваше.

## Этап 4 — Резервные копии (2026-11-27)

1. **Один JSON-файл со всеми таблицами, включая корзину.** Так «заменить» не теряет удалённое, а «объединить»
   переносит и удаления (у удаления свой `updatedAt`). Версия схемы внутри; копию из более новой версии не принимаем.
2. **«Объединить» = новее побеждает по `updatedAt`** — то же правило, что будет у синхронизации (Этап 4.5).
3. **Импорт отменяемый.** Вся операция — одно действие слоя действий; «Отменить» возвращает данные как были.
   Перед «Заменить» — второе подтверждение и совет сначала сохранить копию.
4. **Шифрование: PBKDF2-SHA256 (310 000 итераций, соль 16 байт) → AES-GCM 256 (iv 12 байт)** — встроенный WebCrypto,
   без библиотек; работает в Safari iOS и Chrome. Пароль нигде не хранится — интерфейс честно предупреждает, что
   без него копию не открыть. Минимум 6 символов, ввод дважды.
5. **«Сохранить копию в iCloud» = системное «Поделиться»** (Web Share API с файлом) → «Сохранить в Файлы» → iCloud Drive.
   Прямого доступа к iCloud у веб-приложения нет. На ноутбуке — обычная загрузка. Если «Поделиться» закрыли,
   копия не считается сделанной.
6. **Напоминание о копии — баннер на главной**, если прошло ≥ 7 дней (или копий не было, а своих записей ≥ 5 —
   на пустом приложении и демо-данных не надоедаем). «Позже» скрывает на 2 дня. Отметка последней копии —
   настройка устройства, в копию не входит.
7. **Корзина 30 дней**: автоочистка при каждом запуске приложения; «Удалить навсегда» и «Очистить» тоже отменяемы
   (пока приложение открыто). Окончательное удаление сейчас удаляет запись полностью; для синхронизации (Этап 4.5)
   понадобятся «надгробия» (id + время удаления), чтобы удаление дошло до другого устройства.
8. **.ics — копия дела в Календаре iPhone**, а не подписка: без сервера подписку не обновить. Время «плавающее»
   (без часового пояса) — календарь показывает его в поясе телефона, как и Life OS. Для дел на весь день
   напоминания считаются от полуночи («в день, 9:00» = +9 ч, «накануне, 19:00» = −5 ч).
   Ежемесячный платёж 31-го → `BYMONTHDAY=-1` (последний день месяца, как в приложении).
9. **.ics открывается загрузкой, а не «Поделиться»**: Safari на iPhone на загрузку `.ics` сразу показывает окно
   «Добавить все» в Календарь, а в окне «Поделиться» пункта «Календарь» может не быть.
   Имя файла — латиницей: при проверке Chromium терял кириллические имена загрузок.
10. **Дни рождения**: генератор `birthdayItem` готов (ежегодно, весь день, напоминания в день и накануне); кнопка
    появится в разделе «Люди» (Этап 6). До этого день рождения можно завести событием «весь день» с повтором
    «каждый год» и добавить в календарь из него.

## Этап 3 — Финансы (2026-11-26)

1. **Остаток счёта не хранится**, а считается по операциям (начальный остаток + операции). Нечему рассинхронизироваться, отмена и синхронизация работают сами.
2. **Регулярные платежи не списываются автоматически.** Без сервера приложение не знает, прошла ли оплата; автосписание создавало бы фальшивые расходы. Платёж показывается заранее, «✓ Оплачено» записывает расход и сдвигает дату, «Пропустить» — без операции.
3. **Копилка — переводом, а не расходом.** Пополнение со счёта — это перевод (`savingsId`), он уменьшает остаток счёта, но не попадает в траты и аналитику. Можно пополнять «без счёта» — просто отметка.
4. **Долги — только учёт**, без операций по счетам: деньги в долг часто наличными «мимо» счетов, и это путало бы бюджет. Частичный возврат уменьшает остаток долга.
5. **Бюджеты — в рублях, повторяются каждый месяц.** Общий бюджет месяца (`__total`) необязателен; если его нет, виджет на главной показывает сумму бюджетов по категориям. Оранжевый с 80%, красный — только сверх лимита (по SPEC красный — только для превышений).
6. **Цвета графиков**: доход — изумрудный `#10b981`, расход — индиго `#818cf8` (не красный — он для превышений). Пара проверена валидатором различимости (в т.ч. дальтонизм) на тёмной и светлой теме; на светлой контраст ниже 3:1, поэтому у графиков есть легенда, подписи сумм и переключатель «Таблица». Цвета категорий — те же, что у иконок категорий.
7. **CSV с разделителем «;» и BOM** — Excel с русской локалью открывает без мастера импорта. Импорт гибкий: нужны только «Дата» и «Сумма»; без столбца «Тип» знак решает (минус — расход), а если минусов в файле нет — всё расходы. Дубли (дата+тип+сумма+валюта+комментарий) пропускаются; неизвестные счета создаются.
8. **Калькулятор быстрого ввода**: только «+» и «−» (сложить чек из нескольких позиций), тап по категории сразу сохраняет — 3 касания: сумма, категория, готово.
9. **Перевод между валютами**: можно указать, сколько фактически пришло (`toAmount`), иначе — по курсу.
10. **Recharts — только в отдельном чанке «Аналитика»**, остальной раздел без него (главная грузится быстрее).

## Этап 0–2 (2026-11-26)

1. **HashRouter** (`/#/tasks`) вместо обычных путей. GitHub Pages не умеет отдавать `index.html` на любой путь — при обновлении страницы был бы 404. Хеш-адреса работают всегда и в PWA тоже.
2. **Base path `/LIFE-OS/`** в `vite.config.ts` и manifest (`start_url`, `scope`) — как имя репозитория.
3. **Даты строками `YYYY-MM-DD` в локальном времени**, своя маленькая библиотека `src/lib/dates.ts` — без date-fns/dayjs, меньше вес и нет ошибок с часовыми поясами.
4. **Мягкое удаление (`deletedAt`)** везде — сразу под корзину на 30 дней и синхронизацию.
5. **Слой действий с отменой**: все изменения через `src/actions`, каждое действие записывает «снимок до» → кнопка «Отменить» в тостах. Этот же слой будет использовать ИИ-чат.
6. **Подсказки захвата только предлагаются.** Текст сохраняется как написан; дата/время/сумма показываются чипами, неверную можно убрать крестиком. Применяются только при разборе (тап «Задача»/«Расход»).
7. **«В пятницу», сказанное в пятницу, = сегодня.** Короткие формы дней (пн, вт…) распознаются только с предлогом, чтобы не ловить случайные слова. Дата без года в прошлом → следующий год.
8. **«в 15» без валюты — время, а не сумма.** Сумма — последнее «свободное» число в тексте.
9. **Повторяющиеся задачи**: при выполнении создаётся следующая копия (история выполненных сохраняется). Повторяющиеся события — одна запись, вхождения считаются на лету; перетаскивание переносит всю серию (тост говорит об этом), можно удалить одно вхождение.
10. **Тема и «упростить размытие» — в localStorage**: это настройка устройства (iPhone и ноутбук могут отличаться), применяется до загрузки React без «вспышки».
11. **Шрифты системные** (SF Pro на iPhone, Segoe UI на Windows) — без загрузки из сети, работает офлайн.
12. **Канбан**: перетаскивание мышью на ноутбуке (HTML5 DnD). На iPhone HTML5 DnD не работает — там кнопка «→» переносит на день вперёд, а дата меняется в карточке. Касательное перетаскивание — Этап 8.
13. **Календарь на iPhone**: вид «Неделя» — список по дням (7 колонок на 390 px нечитаемы); на ширине ≥640 px — сетка времени. Перетаскивание в сетке работает и пальцем (pointer events, `touch-action: none` на событиях).
14. **Напоминания** — только пока приложение открыто (честно, см. NOTIFICATIONS.md). Опция «за день» убрана, т.к. не сработает при закрытом приложении; максимум — за 2 часа.
15. **Курсы валют по умолчанию** (1 USD = 92 ₽, 1 TJS = 8.5 ₽); с Этапа 3 меняются в «Финансы → Настройки».
16. **Framer Motion `layoutId` не используется внутри шторок**: он мешал удалению шторки из DOM после закрытия (невидимый слой блокировал нажатия). Индикатор переключателя анимируется проще.
17. **Тесты**: Vitest + fake-indexeddb для парсера, повторов и слоя действий; E2E-проверка Playwright выполняется в облаке перед коммитом (скрипт не коммитится — он под конкретную сессию).
18. **Публикация**: `deploy.yml` собирает и публикует при пуше в `main` (сначала гоняет тесты). Для веток и PR — `ci.yml` без публикации.
